# Production reality report

**Scope:** artifact/download integrity and production-readiness evidence reviewed for this change. Source and workflow edits are not evidence that a release has been built, published, installed, or exercised on a device.

This report distinguishes command-verified results from implemented-but-unverified runtime behavior and environment-limited claims. The unauthorized live Firestore deployment is documented in [`HANDOFF.md`](HANDOFF.md).

| Area | Status | Evidence and limits |
|---|---|---|
| Windows/APK generation fallback | REAL | The browser-side and server-side synthetic PE/APK generators and startup pre-generation path were removed. |
| Native download destination | PARTIAL | Local HTTP checks returned 302 redirects to the named GitHub assets. The current GitHub latest release was queried and is `v1.0.8`, with matching APK, EXE, and extension asset names. This proves target availability, not byte-for-byte identity of a production download. |
| Android release integrity | PARTIAL | Local debug build succeeds and package metadata was inspected. Release workflow requires APK signature verification. Signing secret names exist, but `ANDROID_GOOGLE_SERVICES_JSON_BASE64` is missing from GitHub Actions; the release workflow was not run and no signed release APK exists. |
| Windows release integrity | PARTIAL | Local .NET 8.0.425 self-contained `win-x64` publish succeeded. The prior MSB3277 WindowsBase conflict was traced to an unused WebView2 WPF DLL and no longer appears after it was excluded. No Authenticode signature is applied, and no Windows runtime test was run. |
| Extension release integrity | PARTIAL | Packaging validated the MV3 manifest, declared rule resources, unique IDs, boundary-safe top-level domain rules, and archive contents locally (529 rules; reproducible SHA-256 `2455addf222bd5d1015a1f574546ae78065448b5a404e3e99901bce91d7977d0`). This does not establish browser runtime behavior or published-release identity. |
| Release checksums | PARTIAL | The release job generates and verifies one `.sha256` sidecar per attached artifact. No release job ran to create or independently compare published assets. |
| Firestore owner rules and PhoneLink command isolation | PARTIAL | Pairing sessions remain owner-bound. New PhoneLink device/command paths are UID-scoped, schema-checked, expiry-bounded, and emulator-tested for cross-account access, registered-device enforcement, and duplicate/expired ACKs (13/13 rules tests). The rules were deployed to `raqeeb-production`; Android runtime remains unverified. |
| PhoneLink native flow | PARTIAL | Android Google Sign-In/Firebase Auth registration, Firestore command listening, and client-reported ACK writes are implemented; web commands target registered Android device documents. No Android device runtime was available. There is no independently revocable per-device credential, and an owner-authenticated modified client can forge ACKs. The legacy PhoneLink REST endpoints remain structured 503. |
| Android app blocking and notifications | PARTIAL | The app now lists installed launcher apps for user selection, persists selected package IDs locally, compares actual accessibility window package events, launches the blocker, and posts a local notification on a real match if permission is granted. There is no durable blocked-attempt history; no Android device/emulator runtime was exercised. |
| Windows hosts protection | PARTIAL | Source updates only its marked hosts section, writes via a temp file with `Flush(true)`, verifies the written contents, and flushes DNS. No elevated Windows runtime was exercised. |
| Native runtime behavior | UNVERIFIED | Android device/emulator runtime was not exercised. Windows executable was built but not launched because it requests administrator rights and automatically writes to the real hosts file on startup. |
| Unauthenticated web app runtime | PARTIAL | Production build returned HTTP 200 and rendered the sign-in screen in installed Edge; the logo loaded. No Google OAuth, authenticated workflow, or browser extension behavior was tested. |
| Platform enforcement and AI behavior | UNVERIFIED | Android/Windows enforcement was not runtime-tested. AI online/local/fallback behavior was not fully audited in this pass; see the implementation matrix and security report. |
| Android UsageStats measurement | PARTIAL | `UsageStatsManager.queryEvents` computes local foreground-session totals after Usage Access is granted. No synthetic usage is generated. Android event reporting is asynchronous and may lag recent app transitions. No device runtime was exercised; measurements are not synchronized to the web dashboard. |
| Web/device usage honesty | PARTIAL | The web timer counts only while the Raqeeb tab is visible and focused, resets the legacy counter once, and no longer increments Windows device totals. Aggregation tests confirm an empty account has no measured days or composite score and that one confirmed prayer is divided only by the measured day's five opportunities. Missing dates are excluded from measured-day charts. Other screens still need a full coverage audit. |

Latest web TypeScript check, production Vite build, anti-fake, extension, and analytics-data tests passed. The web build emitted a large-chunk warning. Firestore Emulator rules tests passed 13/13. Rules were deployed to `raqeeb-production` without approval; this is an incident, not a release verification. Android `assembleDebug` passed with current source, but no Android device is attached. Windows self-contained publish passed with the reproduced MSB3277 warning eliminated; no Windows runtime was attempted because startup edits the real hosts file. These checks do not verify a release signer, target-device behavior, or published assets. The existing `v1.0.8` release has no checksum sidecars; no release workflow, tag, or publication was run. The live cross-account denial test, Android E2E, Windows isolated-VM E2E, Authenticode signing, authenticated browser/extension E2E, and release integrity verification remain unverified.
